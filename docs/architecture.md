# Архитектура

Black Shift состоит из трёх частей:

| Часть | Язык | Роль |
|---|---|---|
| `server/` | Elixir / Erlang OTP 27 | Авторитетная симуляция, подбор игроков, сеть, хранение результатов |
| `client/core/` | Rust (`staticlib`, C ABI) | Процедурные модели, скелетный боец, процедурный атлас для экспорта |
| `client/app/` | C++17 / Qt 6 / OpenGL 2.1 | Окно, ввод, сеть, HUD, 3D-рендер |

Клиент и сервер общаются по TCP строками JSON ([протокол](protocol.md)). Сервер — единственный источник правды: клиент присылает только ввод, а позицию, урон, очки и таймеры считает сервер.

## Сервер

### Дерево процессов

```text
BlackShift.Supervisor (rest_for_one)
├── Persistence.Store            схема и таблица Mnesia
├── Match.Supervisor             DynamicSupervisor, не больше 64 матчей
│   └── Match.Server × N         один процесс на матч, симуляция 20 Гц
├── Match.Matchmaker             FIFO-очередь, мониторит ждущие сессии
├── Network.SessionSupervisor    DynamicSupervisor, не больше 256 соединений
│   └── Network.Session × N      один процесс на TCP-соединение
└── Network.Listener             слушающий сокет и цикл accept
```

`rest_for_one` отражает зависимости. Например, если упадёт Matchmaker, перезапустятся сессии и Listener, и ни один клиент не останется в потерянной очереди. При отказе Store перезапускается всё зависимое поддерево. Лимиты `max_matches` и `max_sessions` задаются в `config/config.exs`.

### Симуляция

Состояние матча — обычная Elixir-map, ею владеет только `Match.Server`. Ввод приходит в mailbox, `Game.step/1` — чистая и детерминированная функция. Каждый тик выполняется по порядку:

1. обновляются игроки (решения ботов, движение, способности, стрельба);
2. обновляются постройки и дроны;
3. срабатывают аптечки;
4. пересчитывается реле;
5. проверяются условия победы.

Тик планируется по монотонному времени. Опоздавший тик не порождает очередь «догоняющих». Снимки уходят 10 раз в секунду: каждый второй тик и при завершении матча.

### Сеть и изоляция

`Session` читает сокет в режиме active-once и проверяет каждое сообщение: корректный JSON, не больше 4 КБ, не больше 120 сообщений в секунду. Сокет-операции выполняет только сессия: матч отправляет снимки через `Session.deliver/2`. Если в исходящей очереди сессии набирается 32 сообщения, сессия отключается. Поэтому медленный клиент не тормозит симуляцию.

`Match.Server` и `Session` имеют `restart: :temporary`:

- отключившегося игрока заменяет бот, а матч без клиентов завершается;
- если матч падает, его сессии получают ошибку, а остальные матчи продолжают работу;
- упавший матч не создаётся заново под видом продолжения.

### Хранение

Результат матча записывается через Mnesia `sync_transaction` с последующим `sync_log`. Сообщение `result` клиенты получают только после успешной записи. При ошибке запись повторяется раз в секунду. Таблица `match_results` хранится как `disc_copies` на одном узле, кластеризация не настроена. Живые матчи в базу не пишутся.

## Клиент

### Rust-ядро (`client/core`)

| Модуль | Содержимое |
|---|---|
| `mesh/` | `MeshBuilder` (треугольники, блоки, скошенные призмы, трубы), модели `Model` |
| `actor/` | Скелетный боец: поверхность из поля расстояний (`surface`), кости, походка и скиннинг (`rig`) |
| `atlas` | Процедурные текстуры 64×64 для экспорта ассетов |
| `ffi` | Все `extern "C"` функции; заголовок — `include/blackshift_core.h` |

### Qt-приложение (`client/app`)

| Каталог | Классы | Ответственность |
|---|---|---|
| `app/` | `GameWidget` | Окно и экраны (меню → подключение → матч → результат), таймеры, события |
| `net/` | `ServerConnection`, `protocol::` | TCP, разбор строк JSON, таймаут подключения, ping |
| `game/` | `MatchState` | Карта из `start` и последний снимок; поиск своего игрока и зон |
| `input/` | `InputController` | Клавиши, мышь, углы обзора, сборка сообщения `input` |
| `ui/` | `DeploymentPanel`, `paintMenu`, `paintHud`, `theme::` | Форма подключения, экран меню, HUD, цвета и шрифты |
| `render/` | `SceneRenderer`, `buildWorldMesh`, `ActorAnimator` | OpenGL-рендер, геометрия мира с запечённым светом, анимация удалённых игроков |

`blackshift_client` — статическая библиотека со всем кодом, кроме `main.cpp`. Из неё собираются игра и нативный тест. Ресурсы (текстура материалов и шейдеры) встраиваются через Qt resources. Подробнее о рендере — в [rendering.md](rendering.md).

## Возможное развитие

Rust используется только в клиенте: в сервере нет NIF и портов. Если профилирование покажет узкое место в геометрии, естественная граница для Rust на сервере — пакетные ray casts и collision queries с ограниченным временем выполнения. Долго работающий NIF мешает планировщику BEAM.
