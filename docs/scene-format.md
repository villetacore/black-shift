# Формат карты (scene format 2)

Источник — `server/priv/maps/foundry.json`. Карта — это список объектов в пространстве, а не массив клеток. Координаты `[x, y, z]` в метрах: x и y — горизонталь, z — высота. Сервер встраивает JSON при компиляции, поэтому после правки карты сервер нужно пересобрать (`scripts/play.ps1` делает это сам).

## Объекты

```json
{"id": "west-bunker", "shape": "box", "position": [4, 9.5, 1.4], "size": [4, 1, 2.8],
 "yaw": 0.0, "material": 2, "uv_scale": 0.5, "collision": true}
```

| Поле | Значение |
|---|---|
| `shape` | `box`, `ramp` (поднимается по локальной оси +X) или `cylinder` (восьмигранная призма) |
| `position`, `size` | Центр и размеры объёма |
| `yaw` | Поворот вокруг вертикали в градусах |
| `material` | Индекс 0–15 в листе материалов (см. [assets.md](assets.md)) |
| `uv_scale` | Повторов текстуры на метр; 0.5 — один повтор на 2 м независимо от размера объекта |
| `collision` | Участвует ли объект в столкновениях, лучах и тенях |
| `model` | Необязательно: `crate`, `barrel`, `vent`, `cabinet` заменяют внешний вид процедурной моделью; столкновения остаются по объёму |

Все формы выпуклые. `World.Geometry` вычисляет для каждого объекта мировые вершины, грани с нормалями наружу, плоскости `[a, b, c, d]` и AABB. Эти данные уходят клиенту в `start.map`. Движение, опора, потолки, видимость и попадания считаются по тем же объёмам: под мостиком можно пройти, по рампе — подняться, на верхней площадке — стоять.

Совпадающие плоскости соседних объектов лучше не накладывать: CSG-редактора нет. Полностью скрытые внутри других объектов грани клиент отбрасывает сам.

## Прочие поля

| Поле | Значение |
|---|---|
| `name`, `format` | Название; формат должен быть `2` |
| `bounds` | `[ширина, глубина, высота]`; граница мира для движения и потолок неба |
| `lights` | `position`, `intensity`, `radius`: точечные источники для запечённого света |
| `sky_color` | Цвет неба, RGB 0–1 |
| `zones` | `name` и `rect` `[x0, y0, x1, y1]` для подписи в HUD; более точные зоны идут раньше общих |
| `floor_z` | Высота базового пола, по умолчанию 0 |
| `spawns`, `cores`, `towers` | По одной точке `[x, y, z]` на команду; старые `[x, y]` используют `floor_z` |
| `objectives` | `x`, `y`, `z`, `name`: точки реле в порядке ротации; z по умолчанию 0 |
| `supplies` | `x`, `y`, `z`: аптечки; z по умолчанию 0 |

## Foundry Heights

Карта 60 × 44 м с шестью зонами: цех с мостиком и рампой, открытый двор, насосная, генераторная, южные сервисные тоннели и погрузочная площадка. Высота потолков в зданиях разная, над двором и погрузкой крыши нет. Южный маршрут проходит через перегородки, северный — через насосную и внешний проход.

В карте 111 объёмов: галерея над двором на высоте 3 м с двумя рампами и проходом под ней, реле на мостике цеха (2.3 м), приподнятая насосная и погрузочная терраса (1.2 м), лестница, косые перегородки и низкие укрытия. Бочки, вентиляция и шкафы добавляют ориентиры. Классическая версия сохранена в `foundry-classic.json`; повторная генерация: из `server/` выполнить `mix run --no-start scripts/build_foundry.exs`.

Навигация — граф всех доступных слоёв метровой сетки, а не одна высота на клетку. Рёбра проверяют опору под площадью бойца, зазор для тела и перепад высот вдоль перехода. Граф прогревается до открытия игрового порта. Пространственный индекс XY с ячейкой 4 м ускоряет поиск объёмов для опоры и движения. Реле, аптечки, дроны и базы используют настоящую высоту; захват и подбор через перекрытие запрещены. Мини-карта показывает стены на текущем этаже.

Тесты проверяют достижимость всех целей с обеих баз, независимые слои под галереей и на ней, подъём реального бота, высоту дронов и взаимодействия с аптечками. Навигация пока не строит прыжковые связи и не поддерживает лестницы-стремянки; узкие проходы меньше шага сетки требуют отдельной настройки.

Это собственный формат объёмов, он не совместим с форматами карт Quake или Counter-Strike. Импорта BSP/VMF и произвольных моделей пока нет.

## Жидкости

Необязательный массив `liquids` содержит объёмы независимо от твёрдых объектов:

```json
{"id":"cooling-water","rect":[31,1,36,2.8],"bottom":0,"surface":1.9,
 "current":[0.35,0],"color":[0.13,0.30,0.29]}
```

`rect` задаёт горизонтальные границы, `bottom` и `surface` — высоты дна и
поверхности, `current` — течение в м/с по X/Y, `color` — RGB 0–1.
Дно и стенки нужно задавать обычными коллизионными объектами. Жидкость не
создаёт опору и не останавливает лучи. Бассейн охлаждения — глубокая вода,
затопление сервисного тоннеля — мелкая. Не размещайте пересекающиеся объёмы:
сервер использует первый найденный объём. Небольшие визуальные волны не меняют
серверную высоту поверхности. Объёмы без `liquids` совместимы с прежними картами.
