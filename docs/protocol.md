# Протокол v1

TCP, порт по умолчанию 7777. Каждое сообщение — один JSON-объект в UTF-8 на отдельной строке (JSON Lines).

Ограничения сервера: сообщение клиента до 4 КБ, не больше 120 сообщений в секунду. Клиента, который молчит 15 секунд или стоит в лобби без `join` 15 секунд, сервер отключает. Строки от сервера (например, `start` с картой) бывают больше 4 КБ: клиент должен собирать строку из TCP-потока целиком.

Реализация: `server/lib/black_shift/network/protocol.ex` и `client/app/src/net/Protocol.h`.

## Клиент → сервер

```json
{"type":"join","version":1,"name":"Operator","class":"ranger","mode":"online"}
{"type":"input","forward":1,"strafe":0,"angle":0.25,"pitch":0.1,"jump":false,"sprint":true,"crouch":false,"fire":true,"reload":false,"ability":false,"view_tick":1234}
{"type":"ping"}
```

- `join` — встать в очередь (`mode: "online"`) или начать тренировку (`"practice"`). `class`: `ranger` или `warden`, любое другое значение даёт `ranger`. Из `name` убираются символы, кроме букв, цифр, пробела, `_` и `-`; длина до 20.
- `input` — текущее состояние управления, рекомендуется ~30 раз в секунду:
  - `forward`, `strafe` ограничиваются диапазоном [-1, 1], по диагонали скорость нормализуется;
  - `angle` — рысканье в радианах (0 = +X, π/2 = +Y), `pitch` ограничивается ±1.15;
  - `jump`, `reload` и `ability` защёлкиваются до ближайшего тика, поэтому короткое нажатие не теряется;
  - `fire`, `sprint` и `crouch` действуют, пока удерживаются. Бег — только вперёд, без приседания и стрельбы; встать из приседа можно, только если над головой есть место;
  - `view_tick` (необязательно) — тик снимка, который клиент показывал. Попадания проверяются по позициям целей на этом тике, но не старше 8 тиков (400 мс);
  - если ввод не приходит секунду, сервер останавливает движение и стрельбу. Координаты из ввода игнорируются.
- `ping` — поддержание соединения; клиент шлёт его каждые 4 секунды.

## Сервер → клиент

| Тип | Поля |
|---|---|
| `hello` | `version`, `id` — идентификатор игрока этой сессии |
| `queue` | `waiting`, `needed` |
| `start` | `match`, `id`, `team` (0 или 1), `map` ([формат карты](scene-format.md)), `tick_rate` |
| `snapshot` | см. ниже; каждый тик, 20 раз в секунду |
| `result` | `match`, `winner` (0, 1 или -1 при ничьей), `saved: true` — отправляется только после записи в Mnesia; затем на том же соединении можно снова отправить `join` |
| `error` | `message` |
| `pong` | — |

### snapshot

| Поле | Содержимое |
|---|---|
| `match`, `tick` | Идентификатор матча и номер тика |
| `seconds` | Секунд до конца матча |
| `players[]` | `id`, `name`, `class`, `team`, `x`, `y`, `z` (высота ступней), `vx`, `vy` (м/с), `angle`, `pitch`, `grounded`, `sprinting`, `crouching`, `hp`, `kills`, `deaths`, `level`, `xp`, `cooldown` и `respawn` (в секундах), `bot`; оружие и обратная связь — см. ниже |
| `entities[]` | `id`, `kind` (`core`, `tower`, `drone`), `team`, `x`, `y`, `hp`, `max_hp`, `target` (id цели или `null`), `warning` (идёт захват цели, выстрела ещё не было) |
| `beams[]` | Трассеры текущего тика: `x`, `y`, `z`, `ex`, `ey`, `ez`, `team`. Это визуальный эффект, а не полный журнал выстрелов |
| `score` | `[cyan, amber]` |
| `relay` | Команда, контролирующая точку, или -1 |
| `capture` | `team` (сторона накопленного захвата или -1), `progress` (0–1), `contested`, `active` (сторона сейчас одна на точке; иначе прогресс затухает) |
| `wave` | `remaining` (секунд до следующей волны), `active` (живых дронов обеих команд) |
| `objective` | `x`, `y`, `name`, `remaining` (секунд до смены), `next_name`, `next_x`, `next_y` |
| `supplies[]` | `x`, `y`, `ready`, `ready_at` (тик) |
| `winner`, `over` | Итог матча |
| `feed` | Последние четыре строки ленты событий |

Координаты в метрах: x и y — горизонтальная плоскость, z — высота.

У игроков дополнительно передаётся `boost` — оставшееся время ускорения Ranger в секундах.
Warden выбирает режим через уже существующий `input.sprint`: `false` — лечение,
`true` — атака. Флаг работает и без движения. Оба режима используют общий `cooldown`.
Владение `relay` сохраняется на пустой/спорной точке, но счёт растёт только при
присутствии одной команды-владельца. Ротация обнуляет владение и захват.

## Безопасность

Игрок определяется сессией, а не полями сообщения. Сессия передаёт ввод только своему матчу. JSON-ключи от клиента остаются строками: сетевые данные никогда не создают атомы Erlang. Снимки раскрывают позиции всех участников, поэтому от wallhack протокол не защищает.

### Вода и подтверждение выстрелов

`input.swim` — необязательное булево поле: удержание Space для всплытия.
`jump` остаётся нажатием, а `swim` — удержанием; отсутствие поля означает false.
При погружении направление взгляда и `forward` задают вертикальную тягу.
В `snapshot.players` добавлены `immersion` (0–1) и `fire_at` (тик следующего
разрешённого выстрела). Клиент использует изменение `fire_at` для отдачи и
вспышки, поэтому удержание мыши больше не даёт постоянную вспышку.
`start.map.liquids` содержит статические водные объёмы, как описано в scene-format.

### Оружие, отдача и попадания

Числа оружия — в `server/lib/black_shift/game/weapons.ex`. Поля игрока в `snapshot`:

| Поле | Содержимое |
|---|---|
| `weapon`, `ammo`, `mag` | Название, патроны в магазине и его ёмкость |
| `reload` | Секунд до конца перезарядки (у SG-12 — до следующего патрона), 0 — не перезаряжается |
| `spread` | Текущий конус точности, рад: растёт от движения, прыжка и очереди, сужается в приседе |
| `recoil`, `recoil_yaw` | Авторитетная отдача, рад. Сервер прибавляет её к `pitch`/`angle` ввода; клиент показывает её в камере, чтобы прицел совпадал с полётом пуль |
| `hits`, `hit_head`, `hit_kill` | Счётчик выстрелов, которые попали, и признаки последнего: в голову, добивание |
| `hurt_at`, `hurt_dir` | Тик последнего ранения и направление на его источник (рад, как `angle`; `null` — падение) |

Попадание по игроку делится на зоны: голова (×1.8 у SM-9, ×1.5 у SG-12), торс (×1), ноги (×0.75).
Урон спадает с дистанцией. Попадания отбрасывают цель; ранение слегка подбрасывает прицел.
